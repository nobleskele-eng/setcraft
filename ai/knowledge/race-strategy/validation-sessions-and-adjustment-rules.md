# Validation purpose

A validation session asks whether the plan is executable, repeatable, and technically stable. It is not a guarantee of meet performance.

# Validation ladder

1. technical segment at submaximal speed;
2. segment at target speed with full recovery;
3. repeated target segments with controlled recovery;
4. broken event with locked checkpoints;
5. race rehearsal when appropriate;
6. competition review and plan update.

Do not jump to a maximal full-event test whenever a lower-cost step answers the question.

# Fixed-distance segment test

Use for start, turn, underwater, or finish.

Record:

- exact boundaries;
- time;
- technical criterion;
- number of valid trials;
- rest;
- conditions;
- variability.

Progress when the target is repeatable, not after one lucky attempt.

# Broken-race validation

Use LaneLab's supplied checkpoints. Define recovery and whether the modeled cumulative result is shown. Label the result as broken and planning-only.

Assess:

- segment target success;
- technical cue success;
- pace loss across repetitions;
- response to recovery;
- whether the last segment remains realistic.

# Pace-repeatability validation

Choose a repeat length that represents the event question. Set a required number of successful repetitions and a miss rule. If the athlete repeatedly misses:

- verify timing and target;
- increase recovery if speed quality is the goal;
- shorten repeat distance if technique cannot be preserved;
- lower the target if it was modeled too aggressively;
- stop when further attempts no longer answer the question.

# Primary-risk rehearsal

Examples:

- swimmer rushes first 50 -> rehearse controlled opening plus transition;
- turns deteriorate late -> time fixed turn segments before and after controlled work;
- butterfly rhythm breaks -> use shorter race segments with a rhythm score;
- distance pace drifts -> use rolling split bands and planned cue points;
- finish is mistimed -> rehearse fixed approach decisions at race speed.

# Adjustment rules

Every strategy should specify:

- **green:** target met and technique stable -> continue;
- **yellow:** small miss or one technical error -> repeat with one cue or modest recovery change;
- **red:** repeated miss, unsafe condition, entered restriction conflict, or severe technical failure -> stop or change the task and follow the coach's real-world process.

# Readiness and health boundary

Validation is coach-supervised. LaneLab cannot medically clear maximal testing or return to sport. Athlete self-ratings may influence the coach's questions but are not measured lactate, fatigue, injury, or readiness.

# Review after competition

Compare:

- actual versus locked checkpoints;
- measured versus modeled segments;
- execution cues achieved;
- primary risk occurrence;
- environmental or tactical context;
- one strategy change and one training change.

Avoid rewriting the story to fit the result. Preserve what the plan predicted before the race.
